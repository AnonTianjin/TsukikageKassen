# 2.2.4 · 退房回大厅的落点兜底

## 一句话

对局结束回不去大厅（人还留在原地、然后卡在正在被回收的世界里）的根因修掉了：
落点不可用时不再静默不传送，而是回落到主世界出生点并告警说明怎么修。

## 症状与根因

服主反馈「对局结束回到大厅也没有了」——人其实还在对局世界里，根本没被传送。

`LobbyManager.sendToLobby()` 把落点交给 `sendToLocation()`，而后者在落点为 `null`
时**只清状态、不传送**。落点来自 `plugins/TaketoriKassen/lobby.yml` 的 `spawn.world`，
`Bukkit.getWorld(name)` 返回 `null`（该世界没在 `bukkit.yml` 的 `worlds:` 里注册、
或者根本没执行过 `/taketori lobby set`）时，落点就是 `null`，且旧代码不打任何日志。

叠加上一层：`RoomManager.unloadAndDelete()` 在世界上还有玩家时 `Bukkit.unloadWorld`
必然返回 `false`，于是「100 毫秒后重试、最多 6 次」的循环一直在空转——人锁在待回收世界里。

顺带查明 2.2.0 移植时丢了原版 `LobbyManager.returnPoint()` 的兜底：原版
`spawn()` 不可用时返回 `Bukkit.getWorlds()` 第一个世界的出生点，我们的版本没有这段。

## 修复

| 问题 | 处理 |
| --- | --- |
| 落点为 `null` → 静默不传送，人卡在对局世界 | `spawnOrFallback()`：回落服务器第一个世界的出生点，只告警一次说明「站到大厅里执行 `/taketori lobby set` 可修正」 |
| `lobby.yml` 配了世界但没加载，无任何提示 | `load()` 打 warning，指明去查 `bukkit.yml` 的 `worlds:`；落点完全没设置时再打一条 |
| 一次传送异常把清药水/解除旁观/还原记分板全打断 | `sendToLocation()` 内 `teleport` 包 `try/catch (RuntimeException)`，记 warning 后继续收尾 |
| 一个人回程出错，整队都回不去 | `GameRoom.endCleanup()` 逐人 `try/catch`，记 `[room <id>] 结算送回大厅时对 <名> 出错：…` 后继续下一人 |
| 世界里有玩家 → `unloadWorld` 恒 false，「5 秒重试」变死循环 | `unloadAndDelete()` 卸载前遍历 `world.getPlayers()` 逐个 warning 并送回大厅 |
| `World` 对象卸载后仍非 `null`，玩家被传进已卸载世界 | `entryPointOf()` 增加按世界名回查 `Bukkit.getWorld(name) == null` |
| `RoomManager.entryPoints` 只增不减 | `leave`、`destroyRoom`、`detachRoom` 三处补 `entryPoints.remove(uuid)`；`leaveForRejoin` 刻意保留（重连窗口内要用） |

## 服主自救（升级前后都能用）

1. **站到大厅里执行 `/taketori lobby set`** —— 落点是 live 读取的，不需要重启，这是最省事的修法。
2. 若执行后仍回不去：确认那个世界在 `bukkit.yml` 的 `worlds:` 里被加载；没注册的世界名
   在 `lobby.yml` 里是无效的。
3. 升级后看日志：出现 `[lobby] 没有可用的返回落点…` 就说明仍在走兜底（功能正常，但大厅没配）；
   出现 `[room <id>] 世界 <名> 卸载前仍有玩家…` 说明有人没被传送成功，那行的玩家名就是线索。

## 兼容性

- 配置版本不变（`config-version: 12`），无需迁移；没有新增配置键。
- 行为变化只在「原本什么都不做」的失败路径上：落点缺失时现在会真的传送（到主世界出生点）
  而不是留在原地。想继续用大厅落点，执行一次 `/taketori lobby set` 即可。
- 构建基线仍是 Paper 26.1.2 + Java 25。
