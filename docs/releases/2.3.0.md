# 2.3.0 · 拆包战模式、统一数据层与战场信息补全

## 新增

- **拆包战模式 `bomb`**：与 `pvp` / `pve` / `sengoku_3v3` 并列（别名 `pvp_bomb` / `cs` / `拆包`）。
  包点三相位只在拆包战房间运行，纯 PVP 不再接管包点；拆包战开局校验包点，没划直接拒绝并提示
  `/taketori arena setbomb`。
  入口：`/taketori sengoku mode bomb`（全局写回 config.yml）、
  `/taketori match mode bomb [房间id]`（单房，等待中可切）、
  `/taketori room create <模板> bomb`，以及建房 GUI 第 36 格与战国管理菜单的「全局 → 拆包战」。
- **统一数据持久化**：`data/DataStore` 把玩家档案（角色绑定 + 隐性标签）与跨局战绩收进同一接口，
  实现 `YamlDataStore` / `SqliteDataStore` / `MySqlDataStore`，`storage.type` 切换。
  表结构 `{prefix}players(uuid, character_id, tag_id)`、`{prefix}stats(player_name, stat_key, stat_value)`，
  统计键名与 `stats.yml` 一致，YAML ↔ SQL 可手工互搬。
  驱动运行期按需加载（类路径 → `plugins/TsukikageKassen/drivers/*.jar`），连不上自动回退 YAML。
- **头顶名牌**：`[角色名] 玩家名`，整条按所属队伍染红 / 蓝，分队、换队、换角色、复活自动刷新。
- **敌方目标罗盘**：快捷栏倒数第二格的指南针，每秒指向最近敌方基地；拆包战拆弹阶段指包点、
  战国指敌方天守阁，抢基地阶段改回指基地。只占空格子，丢了自动补。
- 基地标记增强：描边加密 + 四角立柱 + 12 格光柱（粉尘 + END_ROD）。

## 变更

- 占点读条默认 **20 秒**（原 10 秒）；`base.multi-player-bonus` 默认 **false**（不再按人数叠速）。
- `/taketori character <角色id>` 支持玩家自助，不再只有管理员形态。
- 侧栏标题、开局播报按 PVP / 拆包战 / PVE 分开措辞。

## 修复

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 手持插件武器右键铜钟没反应，箭楼占不下来 | 输入层 LOW 优先级派发右键技能并取消事件，敲钟监听是 HIGH + `ignoreCancelled` | 铜钟判定下沉到 `GameRoom.sengokuBellIndexAt`，输入层先判定再决定是否派发；敲钟监听改 `ignoreCancelled = false` |
| 界面出现 `</color>` 字面量 | MiniMessage 闭标签不匹配 | 四处改为 `</red>` 或省略 |
| 建房 GUI 列不出模板 | 用 `level.dat` 判世界文件夹，26.1 维度模板没有 | 改用 `RoomManager.isWorldFolder` |
| 基地标记每秒抛 `data (Boolean) should be Void` | `spawnParticle` 少传 data，误选泛型重载 | 补齐 data 参数 |
| 拆弹超时后罗盘仍指已还原的包点 | 只判模式没判相位 | 增加 `BASE_FIGHT` 判断 |

## 升级注意

- 已有服务器的 `config.yml` **不会被覆盖**：想用新默认值（占点 20 秒、不加速）请手改，
  或删掉该文件让它重新生成；新增的 `storage` 段同样需要手动补上（或删文件重生成）。
- 要用 SQL 后端：改 `storage.type` 后**重启**（`/taketori reload` 不热切数据库）。
  Paper 26.1 自带 sqlite-jdbc 与 mysql-connector-j；精简构建请把驱动 jar 放进 `drivers/`。
- 拆包玩法需把房间模式切到 `bomb`：此前「有包点就自动跑相位」的行为已移除。
