# 2.2.3 · 房间世界空图的根因修复

## 一句话

房间世界「建是建起来了，但一片空图」的根因修掉了：整份存档根目录当模板时，
插件现在会自动下钻到真正装地形的那一层再复制；模板里根本没有地形时，建房前就拦下并说明原因。

## 症状与根因

服主把完整的 `world/` 拷进 `plugins/TaketoriKassen/moonmaps/<模板名>/` 当模板。2.2.1 的规则是
「带 `dimensions/` 子目录的一律不算世界」，于是这种模板要么被判成「不是世界」，要么（更隐蔽）
被原样复制进 `dimensions/minecraft/<房间名>`——Paper 把外层当存档根目录读，真实地形埋在里层
`dimensions/minecraft/overworld/`，房间世界能加载、能走路，但整片是空图。

## 修复

| 问题 | 处理 |
| --- | --- |
| 整份存档根目录当模板 → 房间空图 | 新增 `templateSource()` 解析到内容层（存档根目录 → `dimensions/minecraft/overworld`，没有 `overworld` 时取第一个维度子目录），建房 / `moonmap load` / 写回 / 导入四处都复制这一层，日志写明下钻位置 |
| 模板没有地形时安静地造空房 | `region/*.mca` 为 0 时**建房前拒绝**，发 `room.template-no-terrain` 并按模板名给出下一步；日志同时打出世界内容目录 |
| 空图时无从判断是「没地形」还是「复制落错」 | 房间世界加载成功后必打 `[room] 房间世界 <名> 已加载：folder=… region=N 文件` |
| 启动清理直接删 `k_tpl_*` 编辑副本，编辑期间崩服等于丢图 | 先转存到 `moonmap-recover/<模板名>` 再删；`moonmap load` 会优先取用转存副本 |

## 文档

- `messages.yml`：`room.moonmap-not-world` 改为准确说法（需含 `region/` 或 `level.dat`，整份存档根目录也可以）；
  新增 `room.moonmap-level-root`、`room.template-no-terrain`。

## 兼容性

- 配置版本不变（`config-version: 12`），无需迁移；没有新增配置键。
- 已存在的空房间世界不会自动补地形：删掉重建（或先按上文把模板地形补齐）即可；玩家数据、角色与武器 id 均不受影响。
- 构建基线仍是 Paper 26.1.2 + Java 25。

## 升级后自检

1. 启动日志里 `moonmap-recover` 相关行说明旧编辑副本被保住了（若有）。
2. 建房后看 `[room] 房间世界 kassen_<N> 已加载：folder=… region=<N> 文件`：`region` 为 0 就是模板本身没地形，不是复制故障。
3. 若提示 `room.template-no-terrain`：`/taketori moonmap load <模板名>` 进编辑世界把地图生成或搭好，再 `/taketori moonmap unload <模板名>` 保存。
