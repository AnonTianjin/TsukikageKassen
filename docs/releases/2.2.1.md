# 2.2.1 · 房间世界在 26.1 维度布局下的兼容

## 一句话

Paper 26.1 把世界收进了 `dimensions/minecraft/<世界名>`，房间/月面模板那套复制与清理按旧布局写的位置一律对齐。

## 修复

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 26.1 维度布局的地图导入/选模板被拒「不是世界」 | 判定只认 `level.dat`，而维度布局本来就没有它 | `level.dat` / `region/` / `entities/` / `data/` 任一存在即视为世界；带 `dimensions/` 子目录的不算（那是服务端根） |
| 旧地图被删 `level.dat` 后永久不可用 | 没有补齐逻辑 | 从服务端主世界拷一份（仅在没有 `data/`、`paper-world.yml`、`dimensions/` 且有 `region/` 或 `entities/` 时），只影响未生成区块；moonmap 写回时从 `<名>_bak` 救援 |
| 房间世界复制到容器根目录，26.1 下加载不到 | 目标目录写死 `getWorldContainer()/<name>` | 目标 / 残留清理 / 编号扫描都走「已加载世界文件夹 → 26.1 维度目录 → 容器根」三级候选 |
| 复制出的世界被 Paper 判定「重复世界」拒绝加载 | 跟着复制了 `data/paper/metadata.dat`（世界 UUID） | 复制时跳过该文件 |
| 世界首次加载偶发失败就整局作废 | 未重试 | 加载失败重试一次，仍失败才报错 |

## 兼容性

- 配置版本不变（`config-version: 12`），无需迁移。
- 角色 id、武器 id、存档与玩家数据都不受影响。
- 构建基线仍是 Paper 26.1.2 + Java 25。
