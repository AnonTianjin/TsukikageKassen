# 2.2.6 · 26.1 模板判定与编辑世界落点

在 Paper 26.1.2 上用假人跑「外部导入地图 → 划场地 → 建房开局」链路时发现的两处问题，
只影响管理员建场地流程，不涉及玩法。

## 修复

- `arena setup` 改成**先校验模板、再建场地**。原顺序是「建场地并保存 → 载入模板」，模板不存在或
  放错层级时场地已经写进 `arenas.yml`：每失败重试一次就多一个空场地，`/taketori doctor`、菜单与
  列表里全是垃圾条目。现在所有前置校验（场地 id、模板名、模板目录形态）都通过后才会落盘。
- `arena setup` 判定模板时不再要求 `level.dat`：26.1 起主世界按维度落盘，模板本身就是
  `moonmaps/<名>/region|data|entities`（没有 `level.dat`），旧判定会把所有 26.1 模板打回，
  场地根本划不了。改为与 `moonmap load` 同一口径（`RoomManager.isWorldFolder`，该方法随之放开
  为 public）。旧版布局（带 `level.dat`）与整份 `world/` 根目录照旧放行。
- `arena setup` 的模板提示拆成两句：目录不存在 → 「找不到模板的世界文件夹」；目录存在但不是世界
  → 「不是一个世界文件夹（需含 `region/`，或含 `level.dat`；整份 `world/` 根目录也可以）」。
  此前两种情况共用一句「找不到」，把层级放反或放了个空目录的人会照着提示去重复 import。
- 进入编辑世界时不再直接落在世界出生点：新增 `RoomManager.templateCenter()`，取体积最大的
  `region/r.X.Z.mca` 那片 512×512 区域的中心。外部导入的地图通常不在原点附近，原行为会把人丢在
  空白处（那一小片空白还会被现场生成，混进模板），管理员容易误判成「地图没导进来」。
  取最大文件而非求全部 region 的包围盒：世界加载时预生成的出生点区块会把包围盒中心拉到两片
  地形之间——首版实现就是这么飞的（落点 2559.5 在实际地图外）。

## 兼容性

- 配置、命令、权限、数据格式都没变，无需迁移。
- 构建基线仍是 Paper 26.1.2 + Java 25。

## 验证

构建：Gradle build 通过，checkCorePurity / checkParamKeys / offlineCheck（10 工具）全绿。
真机验证：`arena setup` 在 26.1 维度模板、旧版 `level.dat` 模板、整份 `world/` 根目录、仅
`region/` 四种形态下都能载入；远处地图（`r.10.10`，方块 5120–5631）落点为 5376.5, 71, 5376.5。
